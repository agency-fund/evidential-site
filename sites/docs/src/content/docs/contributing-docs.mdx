:::note
Cheatsheet for anyone who edits, deploys, or rolls back the Evidential docs site

**Repo:** `github.com/agency-fund/evidential-site`, in `sites/docs/`

**Live site:** [https://docs.evidential.dev](https://docs.evidential.dev)

We use [Nimbus](https://nimbus-docs.com), an [Astro](https://astro.build)-based documentation framework, with its
default theme. Pages are MDX files in `sites/docs/src/content/docs/`, and a page's path there is its URL.

## Getting Started

1. Install [pnpm](https://pnpm.io/installation) and [Task](https://taskfile.dev/docs/installation).

1. Clone the repository and install dependencies and the pre-commit hooks:

   ```bash
   git clone git@github.com:agency-fund/evidential-site.git
   cd evidential-site
   task setup
   ```

1. Preview locally by starting a dev server at [http://localhost:4322](http://localhost:4322):

   ```bash
   task docs:start
   ```

1. Before opening a pull request, check that the site type-checks, its links resolve, and its pages lint clean:

   ```bash
   task docs:build docs:check
   ```

Run `task --list` for the other docs tasks, such as `task docs:preview`, which serves the built site with search.

## Writing pages

- Every page needs a `title` in its frontmatter. Don't repeat it as a `#` heading in the body.
- Add each new page to the sidebar in `sites/docs/astro.config.ts`.
- Callouts use `:::note`, `:::tip`, `:::caution`, and similar blocks. Expandable sections use `<Accordion>`.
- Diagrams use Mermaid, written as ``<pre class="mermaid">{`...`}</pre>`` with the diagram between the backticks.

## Routine content update & deploy

:::caution
docs.evidential.dev is still built and deployed from `agency-fund/evidential-docs` while its hosting moves to this
repository. Until then, the steps below apply to that repository.
:::

After publishing changes and merging the PR into the `docs` branch, the site will be **automatically deployed** by GitHub Actions via the `deploy-docs.yaml` workflow.

You can monitor deployment progress in the **Actions** tab on GitHub.

The `docs` branch holds the source.
The `gh-pages` branch holds the built site and the CNAME file.

## Safe rollback

Revert a broken deploy. Besides reverting to previous or known commit:

### 🏷️ Tag known-good states

Before deploying a major change, tag the source commit so you can easily roll back:

```bash
git tag -a v1.2 -m "Docs v1.2"
git push origin v1.2
```

You can then revert the live site to that state:

```bash
git push -f origin v1.2:gh-pages
```
